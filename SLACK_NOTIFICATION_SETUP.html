Slack Notification Setup — Azure Resource Diff Tool

Purpose: step-by-step procedure to enable Slack notifications for this tool in a new environment (different Function App, different Slack workspace, etc.). This is a one-time setup per environment.

What this feature does: after each run, if any resources were added, removed, or modified, a message is posted to a Slack channel with the change counts, resource names, and buttons linking to the diagram and full diff report. If nothing changed that day, no message is sent — no daily noise. If SLACK_WEBHOOK_URL isn't configured at all, this feature is silently skipped entirely — nothing else breaks.

Part 1 — Create a Slack Incoming Webhook

Works with any Slack account type (personal or organizational) — no special licensing required, unlike Microsoft Teams' Workflows/Power Automate route, which requires an organizational Microsoft 365 account.

  1. Open a browser and go to https://api.slack.com/apps (Note: this is a different site from app.slack.com, which is the Slack chat interface itself — the app/webhook creation happens only on api.slack.com.)
  2. Sign in with your Slack account if prompted
  3. Click Create New App (top right)
  4. Choose Blank app (simplest option — no extra features needed)
  5. Select the workspace you want notifications sent to
  6. Enter an App Name (e.g. Azure Resource Diff Alerts)
  7. Click Create App
  8. In the left sidebar of the app's settings page, click Incoming Webhooks
  9. Toggle Activate Incoming Webhooks to On
  10. Click Add New Webhook to Workspace (appears after activating)
  11. In the channel picker, select the channel you want alerts posted to
  12. Click Allow
  13. Copy the Webhook URL now shown in the table (starts with https://hooks.slack.com/services/...)

Keep this URL safe — anyone with it can post messages to your channel. Treat it like a credential (don't commit it to code, don't share it in chat/tickets).

Part 2 — Add the webhook URL to the Function App

az functionapp config appsettings set \
  --name <your-function-app-name> \
  --resource-group <your-resource-group> \
  --settings SLACK_WEBHOOK_URL="<paste your Slack webhook URL here>"

Verify it saved correctly:

az functionapp config appsettings list \
  --name <your-function-app-name> \
  --resource-group <your-resource-group> \
  --query "[?name=='SLACK_WEBHOOK_URL'].value" -o tsv

Should print your webhook URL back.

Part 3 — Confirm the code supports Slack notifications

The Slack notification logic lives in snapshot_function/__init__.py. Confirm it's present:

grep -c "send_slack_notification" snapshot_function/__init__.py

Should show 2 or higher (the function definition, plus the call inside main()).

If it shows 0, this environment's code doesn't have the feature yet — copy the current snapshot_function/__init__.py and run_local.py from the reference project into this environment before continuing.

Part 4 — Deploy

cd <your-project-folder>
func azure functionapp publish <your-function-app-name> --python

Confirm it ends with Remote build succeeded! and lists snapshot_function - [timerTrigger].

Part 5 — Test with a real change

Since notifications only fire when something actually changed, create a small, disposable test resource:

az group create --name demo-slack-test --location <your-region>

az network vnet create \
  --name demo-slack-vnet \
  --resource-group demo-slack-test \
  --location <your-region> \
  --address-prefix 10.60.0.0/16 \
  --subnet-name demo-subnet \
  --subnet-prefix 10.60.1.0/24

Wait ~30-60 seconds for Resource Graph to index it.

Trigger the function:

MASTER_KEY=$(az functionapp keys list --name <your-function-app-name> --resource-group <your-resource-group> --query masterKey -o tsv)

curl -X POST "https://<your-function-app-name>.azurewebsites.net/admin/functions/snapshot_function?code=$MASTER_KEY" \
  -H "Content-Type: application/json" -d '{}'

sleep 20

Check Slack — the channel selected in Part 1, Step 11 should show a new message with: - 🟢 (or 🔴 if something was removed) header: "Azure Resource Changes — [date]" - Added / Removed / Modified counts - The test VNet listed under "Added resources" - View Diagram and View Full Diff Report buttons (clicking them opens a time-limited, secure link — see Part 6)

Clean up the test resource:

az group delete --name demo-slack-test --yes --no-wait

Part 6 — How the diagram/diff links work (background, not a setup step)

The buttons in the Slack message use a SAS (Shared Access Signature) URL — a time-limited, read-only link generated fresh for each notification, valid for 7 days by default. This keeps the underlying storage containers private while still letting anyone with the link view that specific file, without needing an Azure login or any broader storage access.

If a link stops working after 7 days, that's expected — the next day's notification (if there's a change) will include a fresh link.

Troubleshooting

Symptom Likely cause Fix
No Slack message appears, even after a real change SLACK_WEBHOOK_URL not set, or set incorrectly Re-check Part 2's verification step
No Slack message, but no error in logs either This is expected if nothing actually changed that day — the feature intentionally stays silent on no-change days Not a bug — create a real test change (Part 5) to verify
Slack message appears but buttons give an error/expired link More than 7 days have passed since that specific notification Expected — links expire; check the storage account directly for current files instead
grep -c "send_slack_notification" returns 0 This environment's code predates the Slack feature Copy the latest snapshot_function/__init__.py / run_local.py from the reference project
